# SCN-LIB-001 需求分析（SA）

## 文件資訊

- 需求文件 ID：REQ-LIB-001
- 來源情境：SCN-LIB-001
- UI 設計來源：https://www.figma.com/make/3ilP5JnPlkgXomqo70MsDW/Library-Mini-Admin-Console?p=f&fullscreen=1；本地匯出：`docs/figma/library-mini-admin-console/`
- 分析角色：SA
- 分析日期：2026-09-04

## 1) 需求摘要

- 情境目標：讓管理員以小型管理控制台建立共享書櫃館藏，並追蹤書籍可借數量、借閱人與歸還後的狀態，降低不知道書在哪裡及誰借走的問題。
- 使用者角色：管理員（Figma 顯示為 Admin／管理員）。本情境不處理登入與權限驗證。
- 核心流程：建立書籍及初始數量 → 在館藏列表確認書籍 → 借出一本並記錄借閱人 → 歸還一本並恢復可借數量。
- 主要畫面區塊：`TopBar` 頂端導覽與搜尋輸入框、`TransactionCard` 借書／還書分頁表單、`AddBookForm` 新增書籍表單、`BookTable` 館藏列表，以及表單內聯成功／錯誤訊息與右上角 toast。
- In-scope：新增書籍、設定新增時的初始數量、顯示館藏清單與狀態、借出一本、歸還一本、成功或失敗後更新畫面及提供業務回饋。README 所列「增加 copies」在本情境僅確認為新增時設定數量；獨立增加 copies 操作尚未由 scenario 或畫面定義。
- Out-of-scope：登入與權限、預約、罰款規則、通知、搜尋行為、書籍編輯／刪除、獨立增加 copies 畫面，以及本情境未描述的報表與管理功能。Figma 中可見的搜尋輸入框仍需保留視覺對齊，但是否啟用功能列為待確認。
- 前置條件與外部依賴：管理員已進入管理控制台；書籍與借閱狀態可被系統讀取及更新；前端需以指定 Figma 匯出畫面作為視覺與互動狀態基準；沒有第三方服務依賴被納入本情境。
- 名詞定義：書籍（以 ISBN 或業務確認的書籍識別方式辨識的書目）、副本（同一書籍可借出的單位）、總數（館藏副本總數）、可借數量（尚未借出的副本數）、借閱紀錄（一次借出與歸還的業務關係）、未上架（不可被借出）、讀者識別（scenario 所稱借閱人姓名或 Figma 所稱讀者 ID，實際採用方式待確認）。

## 2) Functional Requirements (FR)

### FR-001 建立書籍與初始館藏

- 使用者／觸發者：管理員在新增書籍區塊填寫資料並提交。
- 前置條件：管理員已開啟管理控制台；新增書籍表單可操作；尚未存在相同書籍識別值的館藏資料。
- 使用者輸入：scenario 要求書名、作者與數量；依 Figma `AddBookForm` 額外呈現 ISBN（必填）、作者（可選）、分類（必填）、數量（必填且至少 1）及上架狀態切換（預設開啟）。ISBN、分類與作者的最終必填性以待確認事項為準。
- 業務行為：驗證必填欄位、數量為正整數及書籍識別值不可重複；建立書籍與初始館藏；成功時可借數量等於總數，若上架則依可借數量呈現可借閱，若未上架則呈現未上架。
- 成功結果：回傳業務成功碼 `00000`；館藏列表出現新增項目，且書名、作者、識別值、分類、狀態及可借數／總數與提交內容一致。
- 失敗結果：回傳 `A0000`；不建立不完整、無效或重複的書籍；表單保留可修正的輸入並顯示可理解的錯誤回饋。

### FR-002 查詢與呈現館藏狀態

- 使用者／觸發者：管理員開啟控制台、完成新增／借出／歸還後查看館藏列表。
- 前置條件：管理控制台可取得目前館藏資料；若沒有任何館藏，系統仍需能呈現空清單狀態。
- 使用者輸入：開啟列表或完成異動後的重新查看；本 FR 不要求管理員輸入搜尋條件。
- 業務行為：呈現每筆書籍的書名、ISBN、作者、分類、狀態、可借數／總數及動作；依目前業務狀態顯示「可借閱」、「已借出」或「未上架」；沒有資料時顯示「尚無館藏」與引導使用新增表單。
- 成功結果：列表資料與最近一次成功異動後的業務狀態一致；可借數量不小於 0 且不大於總數。
- 失敗結果：若無法取得列表，回傳 `B0000`；不以空列表冒充成功，並顯示載入失敗及可重試的 UI 回饋。

### FR-003 借出書籍

- 使用者／觸發者：管理員在借書分頁或館藏列的快速借出動作提交借閱資料。
- 前置條件：指定書籍存在、為上架狀態且可借數量大於 0；借閱人識別與書籍識別已填寫；若到期日功能獲確認，日期需符合業務規則。
- 使用者輸入：Figma 借書表單的讀者 ID（必填）、ISBN（必填）、到期日（可選）；scenario 所稱借閱人姓名與 Figma 讀者 ID 的採用方式待確認。
- 業務行為：確認書籍可借後建立一次借閱關係，使可借數量減少 1；當可借數量降為 0 時狀態改為「已借出」，仍有可借副本時維持「可借閱」；不得使可借數量低於 0。
- 成功結果：回傳 `00000`；館藏列表顯示更新後的可借數量與狀態；畫面提供借出成功訊息，並可指出借閱人及到期資訊（到期規則確認後適用）。
- 失敗結果：回傳 `A0000`；書籍不存在、無可借副本、未上架、借閱人或必要識別值無效時不建立借閱關係、不變更數量，並顯示具體失敗原因。

### FR-004 歸還書籍

- 使用者／觸發者：管理員在還書分頁或館藏列的快速歸還動作提交歸還資料。
- 前置條件：指定書籍存在且至少有一個未歸還副本；ISBN 已填寫；若同一書籍有多個未歸還借閱，需依已確認的讀者識別規則選定要歸還的借閱關係。
- 使用者輸入：Figma 還書表單的 ISBN（必填）及讀者 ID（可選）；是否必須提供讀者識別以避免多筆借閱誤歸還，列為待確認。
- 業務行為：確認存在可歸還的借閱關係後完成歸還，使可借數量增加 1、關閉對應借閱關係；當可借數量等於總數時狀態改為「可借閱」，仍有副本借出時維持「已借出」；不得使可借數量大於總數。
- 成功結果：回傳 `00000`；館藏列表顯示恢復後的可借數量與狀態，畫面提供歸還成功訊息。Figma 顯示的逾期天數與罰款提示不列為已凍結的成功結果，須待確認後才納入。
- 失敗結果：回傳 `A0000`；書籍不存在、沒有借閱紀錄或無法判定對應借閱關係時不增加可借數量、不關閉錯誤借閱關係，並顯示具體失敗原因。

### FR-005 操作結果與畫面狀態回饋

- 使用者／觸發者：管理員完成新增、借出、歸還或觸發上述動作的失敗結果。
- 前置條件：操作已完成業務判定並產生成功或失敗結果。
- 使用者輸入：提交表單、切換借書／還書分頁或點擊館藏列的快速動作。
- 業務行為：成功時更新對應列表或表單狀態並顯示成功提示；失敗時保留可修正輸入、維持原業務狀態並顯示對應錯誤原因；不可只顯示 HTTP 狀態而缺少業務錯誤碼。
- 成功結果：管理員可從內聯訊息或 toast 判斷操作結果，且畫面資料與成功業務結果一致。
- 失敗結果：管理員可辨識需修正輸入、不可借閱／歸還或系統暫時失敗等原因；重試不會重複建立或重複歸還同一筆業務結果。

| 目前狀態 | 觸發動作 | 條件 | 下一狀態 | 使用者可見結果 |

### FR-UI-001 前端畫面對齊設計

- 前端畫面需對齊 `https://www.figma.com/make/3ilP5JnPlkgXomqo70MsDW/Library-Mini-Admin-Console?p=f&fullscreen=1` 的指定畫面，並以本地匯出 `docs/figma/library-mini-admin-console/` 及下列元件作為可重現基準：`src/app/App.tsx`、`src/app/components/TopBar.tsx`、`src/app/components/TransactionCard.tsx`、`src/app/components/AddBookForm.tsx`、`src/app/components/BookTable.tsx`。
- 頁面需保留 Figma 的整體區塊順序：頂端白色導覽列；桌面寬度下左右兩欄的借／還操作卡與新增書籍卡；下方館藏列表；窄螢幕時兩欄改為可閱讀的單欄排列，館藏表格可水平查看。
- `TopBar` 需對齊品牌圖示與 Library Mini Admin／管理控制台文字、右側 Admin／管理員資訊，以及可見的搜尋輸入框。搜尋輸入框目前只要求視覺存在與對齊，其實際搜尋行為不在本情境範圍。
- `TransactionCard` 預設顯示借書分頁，並提供還書分頁；借書需顯示讀者 ID、ISBN、可選到期日與確認借出；還書需顯示 ISBN、可選讀者 ID 與確認歸還。必填與可選標示、分頁選取色彩、欄位提示文字需對齊指定畫面。
- `AddBookForm` 需顯示書名、ISBN、作者、分類、數量、上架狀態切換與新增書籍按鈕；欄位的必填／可選狀態須與已確認的業務規則一致，未確認差異需記錄於待確認事項。
- `BookTable` 需顯示書名、ISBN、作者、分類、狀態、可借數／總數及動作欄；狀態徽章需能呈現可借閱、已借出、未上架；可借數為 0 或未上架時快速借出需呈 disabled，沒有借出副本時快速歸還需呈 disabled。
- 空列表、成功、驗證失敗、業務拒絕及系統失敗均需有與 Figma 同層級的畫面回饋；成功與失敗不得只更新 toast 而遺漏主畫面資料或錯誤狀態。
- UI 對齊驗收以指定 Figma 畫面與元件狀態為基準；若業務確認結果需要偏離畫面，須在差異清單中記錄區塊、原因、採用結果及核准者，不能默默偏離。

## 3) Non-Functional Requirements (NFR)

### NFR-001 業務一致性

- 類型：一致性
- 需求：每次新增、借出、歸還的成功結果都必須同時反映在館藏數量、狀態與借閱關係；成功後再次查看列表不得出現可借數量低於 0 或高於總數的結果；失敗不得留下部分更新。
- 驗證方式：以成功與失敗案例各執行一次，並於每次操作後查看列表與下一次可操作狀態；覆蓋最後一本借出、最後一本歸還及重複提交。
- MVP 目標或限制：先保證單一業務操作的可觀察結果一致；多管理員同時異動的衝突策略需在架構與 SD 階段確認。

### NFR-002 可用性與可理解回饋

- 類型：可用性
- 需求：所有輸入欄位須有清楚標籤、必填／可選提示及可理解的錯誤訊息；成功、業務拒絕與系統失敗需能被管理員區分；不可操作的快速動作須呈 disabled 狀態。
- 驗證方式：依 FR 與 AC 逐一操作表單、分頁、空列表及 disabled 動作，確認不需閱讀開發者資訊即可判斷下一步。
- MVP 目標或限制：沿用 Figma 的繁體中文介面文字與色彩語意；文案細節若因錯誤碼定稿而變更，需同步更新 UI 對齊差異清單。

### NFR-003 Figma 視覺與互動對齊

- 類型：相容性／可用性
- 需求：前端需對齊指定 Figma 匯出畫面的布局、區塊層級、欄位順序、分頁／按鈕／徽章狀態、空狀態及成功失敗回饋；業務邏輯不得使已確認的畫面狀態失去可辨識性。
- 驗證方式：以指定 Figma URL 與 `docs/figma/library-mini-admin-console/src/app/components/` 下五個情境元件逐區塊比對正常、disabled、空列表及錯誤狀態；差異須有清單與核准結果。
- MVP 目標或限制：Figma Make export snapshot 是本次 UI 基準，未提供額外設計 guideline；不要求實作 Figma 未定義的額外頁面。

### NFR-004 錯誤處理可追蹤性

- 類型：可觀測性／可靠性
- 需求：所有成功與失敗結果都必須攜帶並映射全域業務錯誤碼 `00000`、`A0000`、`B0000` 或 `C0000`；HTTP status 不得取代業務錯誤碼；UI 顯示內容需能對應到本文件的錯誤情境。
- 驗證方式：檢查新增、借出、歸還及讀取列表的成功、客戶錯誤、系統錯誤情境，確認錯誤碼存在、UI 映射正確且失敗不改變業務狀態。
- MVP 目標或限制：本情境沒有第三方服務，因此 `C0000` 暫不應被觸發；SD 負責定稿完整錯誤碼文件與 API 契約。

### NFR-005 正常操作回應

- 類型：效能／可用性
- 需求：在正常服務與合理資料量下，管理員提交一次有效操作後，畫面應在同一操作流程內呈現成功或失敗結果，並可立即判斷下一步；不要求以背景輪詢或額外手動刷新才能看見本次結果。
- 驗證方式：於新增、借出、歸還各執行一次，觀察提交後訊息、列表數量、狀態徽章與動作 disabled 狀態是否在同一流程完成更新；具體量化 SLA 由 Archi 階段確認。
- MVP 目標或限制：MVP 先以可完成且可驗證的互動流程為目標，不在 SA 階段指定架構、部署或成本方案。

## 4) Acceptance Criteria (AC, Given/When/Then)

### AC-001 新增有效書籍

- Given 管理員在新增書籍表單填入有效書名、ISBN、分類及至少為 1 的數量，作者可依已確認規則填寫或留白，且識別值尚未存在
- When 管理員提交新增書籍
- Then 系統回傳業務碼 `00000`，館藏列表新增該書，初始可借數量等於總數，並依上架狀態顯示正確狀態徽章與成功回饋

### AC-002 新增欄位驗證失敗

- Given 管理員未填寫已定義的必填欄位，或輸入非正整數數量
- When 管理員提交新增書籍
- Then 系統回傳 `A0000`，不新增書籍，表單保留可修正輸入並在對應區塊顯示驗證錯誤

### AC-003 阻擋重複書籍識別值

- Given 館藏列表已存在相同 ISBN 或已確認的書籍識別值
- When 管理員以該識別值提交新增書籍
- Then 系統回傳 `A0000`，不增加館藏筆數，並顯示識別值已存在的內聯錯誤或 toast

### AC-004 借出仍有可借副本的書籍

- Given 指定書籍存在、為上架狀態、可借數量大於 0，且管理員填寫有效借閱人識別與 ISBN
- When 管理員提交借出
- Then 系統回傳 `00000`，可借數量減少 1；若仍有副本可借則狀態維持可借閱，並顯示借出成功回饋

### AC-005 借出最後一本副本

- Given 指定書籍為上架狀態且可借數量為 1，管理員填寫有效借閱人識別與 ISBN
- When 管理員提交借出
- Then 系統回傳 `00000`，可借數量變為 0，狀態顯示已借出，且借出動作進入 disabled 狀態

### AC-006 阻擋不可借出的書籍

- Given 指定書籍不存在、未上架或可借數量為 0
- When 管理員提交借出或嘗試使用館藏列的快速借出
- Then 系統回傳 `A0000` 或在前端阻止 disabled 動作，不建立借閱、不改變可借數量，並顯示對應原因

### AC-007 歸還已借出的書籍

- Given 指定書籍存在且至少有一個未歸還副本，管理員填寫有效 ISBN，必要時補充可唯一判定借閱人的識別
- When 管理員提交歸還或使用館藏列的快速歸還
- Then 系統回傳 `00000`，可借數量增加 1；若已全部歸還則狀態變為可借閱，否則維持已借出，並顯示歸還成功回饋

### AC-008 阻擋無借閱紀錄的歸還

- Given 指定書籍不存在、沒有未歸還副本，或多筆借閱下缺少必要的判定資訊
- When 管理員提交歸還
- Then 系統回傳 `A0000`，不增加可借數量、不關閉任何錯誤借閱，並在還書區塊顯示可理解的失敗原因

### AC-009 空館藏列表

- Given 館藏資料取得成功且目前沒有任何書籍
- When 管理員開啟館藏列表
- Then 系統回傳 `00000`，顯示「尚無館藏」空狀態與引導使用右側表單新增書籍，不顯示不存在的書籍動作

### AC-010 系統錯誤維持原狀態

- Given 館藏或借閱異動因系統原因無法完成
- When 管理員執行新增、借出或歸還
- Then 系統回傳 `B0000`，不產生部分更新，原有列表數量與狀態維持不變，並顯示可重試的系統錯誤回饋

### AC-UI-001 前端畫面對齊驗收

- Given FE 依需求實作 `https://www.figma.com/make/3ilP5JnPlkgXomqo70MsDW/Library-Mini-Admin-Console?p=f&fullscreen=1`，並以 `docs/figma/library-mini-admin-console/` 的 `App.tsx`、`TopBar.tsx`、`TransactionCard.tsx`、`AddBookForm.tsx`、`BookTable.tsx` 作為比對材料
- When 檢查桌面與窄螢幕的主要布局、借書／還書分頁、新增書籍表單、館藏欄位與狀態徽章、快速動作 disabled、空列表、內聯訊息及 toast 等指定 UI 區塊與互動流程
- Then 前端畫面需與 Figma 設計來源在區塊順序、欄位順序、文字語意、狀態呈現、操作回饋及可操作性上對齊；任何差異都必須附差異清單、原因、採用結果與核准資訊，否則驗收不通過

## 業務錯誤情境與錯誤碼需求

> 本需求使用 `AGENTS.md` 已定義的全域業務碼：`00000` 成功、`A0000` 用戶端／業務輸入錯誤、`B0000` 系統錯誤、`C0000` 第三方錯誤。HTTP status 不得取代業務碼；更細的錯誤子碼、response envelope 與 API 契約由 SD 定稿。

| 錯誤情境 | 建議業務碼 | 觸發條件 | 使用者可見訊息 | UI 處理 | 可重試 |
| --- | --- | --- | --- | --- | --- |
| 新增欄位缺漏或格式不正確 | `A0000` | 必填欄位缺漏、數量非正整數或識別值格式不合規 | 請修正必填欄位或數量格式 | 保留輸入，欄位或表單顯示錯誤，不新增 | 是，修正後 |
| 書籍識別值重複 | `A0000` | ISBN 或已確認的唯一識別值已存在 | 書籍識別值已存在，無法重複新增 | 顯示內聯錯誤與 toast，列表不變 | 是，改用其他值 |
| 書籍不存在 | `A0000` | 借出／歸還找不到指定書籍 | 找不到該書籍 | 保留表單，提示重新確認識別值 | 是 |
| 書籍無可借副本 | `A0000` | 可借數量為 0 | 該書籍已全數借出 | 快速借出 disabled；提交時顯示錯誤 | 狀態更新後 |
| 書籍未上架 | `A0000` | 書籍狀態為未上架 | 該書籍未上架，無法借閱 | 顯示未上架徽章，借出動作 disabled | 上架後 |
| 沒有可歸還的借閱 | `A0000` | 沒有未歸還副本或無法判定對應借閱 | 該書籍沒有可歸還的借閱紀錄 | 不改數量，還書區塊顯示錯誤 | 補充正確資料後 |
| 數量／狀態衝突 | `A0000` | 會使可借數量低於 0、高於總數或關閉錯誤借閱 | 書籍狀態已變更，請重新確認後再試 | 拒絕異動，重新取得狀態 | 是，取得最新狀態後 |
| 系統讀取或更新失敗 | `B0000` | 服務無法完成列表讀取或異動 | 系統暫時無法完成操作，請稍後重試 | 顯示錯誤，不以空資料或成功資料覆蓋畫面 | 是 |
| 第三方服務失敗 | `C0000` | 本情境目前未納入的第三方依賴失敗 | 外部服務暫時無法使用 | 目前不應觸發；若 SD 納入依賴，需沿用全域錯誤映射 | 依第三方恢復狀態 |
