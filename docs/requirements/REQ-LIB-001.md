## 1) 需求摘要與範圍

### 1.1 業務目標

讓共享書櫃管理者能建立書籍、查看館藏狀態、記錄借出與歸還，並在每次操作後知道可借數量與處理結果。

### 1.2 範圍

本需求納入：

- 建立書籍資料，包含書名、ISBN、作者、分類、館藏數量與上架狀態。
- 顯示館藏清單、書籍狀態及可借數量／總數。
- 依 ISBN 與借閱人識別資訊辦理借書。
- 依 ISBN 辦理還書，並更新可借數量與狀態。
- 呈現成功結果與可供使用者處理的業務錯誤。
- 前端畫面對齊指定 Figma 來源的主要 UI 區塊。

### 1.3 不在本次範圍

- 登入、權限、預約、罰款制度、通知。
- 書籍搜尋功能；雖然 Figma export 的 TopBar 有搜尋欄，但 repo tutorial scope 明確排除搜尋。
- 未經確認的借閱歷史查詢、報表及批次匯入。
- 架構、資料庫 schema、API schema 與成本估算；這些交由 Archi／SD 處理。

### 1.4 UI 區塊與設計依據

Figma Guidelines 目前為空白範本，沒有額外的產品設計規則，因此以 Figma export 的現況作為本次畫面參考。前端需對齊下列區塊：

## 2) Functional Requirements (FR)

### FR-001 建立書籍

- 系統應提供建立書籍的操作，必填書名、ISBN、分類與館藏數量；作者為可選欄位。
- 館藏數量必須為大於或等於 1 的整數。欄位未填或格式不符時不得建立資料。
- ISBN 在館藏中必須唯一；重複 ISBN 不得建立第二筆書籍。
- 上架狀態由表單提供。新增為上架時，初始狀態為「可借閱」；新增為未上架時，初始狀態為「未上架」。初始可借數量等於總數量。
- 建立成功後，新增書籍應出現在館藏列表，並顯示成功結果。

### FR-002 顯示館藏與可借狀態

- 系統應顯示館藏列表，至少呈現書名、ISBN、作者、分類、狀態、可借數／總數與動作欄位。
- 狀態至少包含「可借閱」、「已借出」及「未上架」。當可借數量為 0 時，該書不得再被借出。
- 書籍尚無資料時，應顯示空狀態，並引導管理者使用新增書籍表單。
- 每筆書籍應提供借出與歸還動作；無可借副本或未上架時，借出動作不可用；沒有借出中的副本時，歸還動作不可用。
- 借出或歸還成功後，列表中的數量與狀態應反映最新結果。

### FR-003 借書

- 系統應要求管理者提供 ISBN 與借閱人識別資訊，並確認該 ISBN 對應到存在、上架且仍有可借副本的書籍。
- 借書成功時，可借數量減少 1；若減至 0，狀態變更為「已借出」，若仍有可借副本則維持「可借閱」。
- 系統應保留足以讓後續還書對應的借閱資訊。借閱人欄位目前依 Figma export 顯示為「讀者 ID」，其與情境中的「借閱人姓名」是否為同一業務概念，列為待確認事項。
- 到期日欄位在 Figma export 為可選；是否啟用預設到期日及其規則，須依待確認事項決定後由 SD 凍結契約。

### FR-004 還書

- 系統應要求管理者提供 ISBN，並確認該書有可歸還的借閱中副本；讀者 ID 可依目前 UI 作為選填識別資訊。
- 還書成功時，可借數量增加 1；當可借數量恢復為總數量，狀態變更為「可借閱」。
- 歸還完成後，對應的借閱中資訊不得再被視為未歸還，並應提供成功結果。
- 逾期天數與罰款提示出現在 Figma export，但不在 `SCN-LIB-001` 的業務敘述內；在規則確認前，不將其視為已凍結的計費需求。

### FR-005 業務結果與錯誤回饋

- 每次新增、借出、歸還操作都應回傳成功或業務錯誤結果，前端不得只依 HTTP status 判斷成功與否。
- 前端應依業務錯誤碼顯示可理解的繁體中文訊息，並在失敗時維持原本館藏狀態。
- 成功操作應同步更新相關畫面；失敗操作不得造成數量、狀態或借閱資訊的部分更新。

### FR-UI-001 前端畫面對齊指定 Figma

- 前端頁面必須以 `docs/figma/library-mini-admin-console/` 及其 README 所列 Figma URL 為指定設計來源，對齊頁首、借還操作卡、新增書籍表單、館藏列表／空狀態、回饋提示等區塊的結構、順序、文案層級、控制項狀態與視覺層次。
- 任何因業務流程需要的欄位或錯誤狀態，應在上述對應區塊內呈現，不得任意移除或改變主要操作意圖。
- UI 對齊不得破壞既有 `data-testid` locator；目前 Figma React export 未掃描到 `data-testid`，實際應用程式若已有 locator，交付時仍須保留其語意與穩定性。

## 3) Non-Functional Requirements (NFR)

### NFR-001 UI 一致性

- 在相同內容與狀態下，前端主要區塊、資訊層級、控制項文案、成功／錯誤視覺回饋應與指定 Figma export 對齊；未經核准的差異須列入交付說明。

### NFR-002 可操作性與可理解性

- 所有輸入欄位應有可辨識標籤；必填欄位、不可用動作與操作結果應可由使用者理解。
- 借書、還書、新增書籍的操作結果應在原操作區域或明確的通知區域呈現，不得只以不可追蹤的狀態變化表示。

### NFR-003 響應式呈現

- 在窄畫面時，新增書籍與借還操作區應能由雙欄收合為可閱讀的單欄；館藏列表可水平捲動但不得隱藏必要欄位或動作。

### NFR-004 狀態一致性

- 成功的借出／歸還／新增操作完成後，列表與操作區顯示的書籍數量、狀態及可用動作應一致；失敗時不得顯示成功狀態。

### NFR-005 業務錯誤可追蹤

- 所有業務失敗結果都應帶有本文件定義的業務錯誤碼；HTTP status 僅作傳輸層資訊，不得取代業務錯誤碼。

### NFR-006 UI 測試定位穩定性

- 前端實作與 UI 調整應保留既有 `data-testid` 完整性。若後續為本需求新增 locator，名稱與綁定區塊須在 QA 測試文件中固定並可重複使用。

## 4) Acceptance Criteria (AC, Given/When/Then)

### AC-001 新增有效書籍

- Given 管理者在「新增書籍」表單填入未使用的 ISBN、書名、分類及大於等於 1 的館藏數量
- When 管理者送出新增
- Then 系統建立一筆書籍，初始可借數量等於總數量，並在館藏列表顯示該書及成功訊息

### AC-002 阻擋無效或重複書籍

- Given 管理者未填必填欄位、輸入無效數量，或輸入已存在的 ISBN
- When 管理者送出新增
- Then 系統拒絕建立，回傳對應業務錯誤碼與繁體中文訊息，館藏列表與既有資料不變

### AC-003 顯示館藏狀態

- Given 系統已有至少一筆書籍，且各書籍可能有不同可借數量與狀態
- When 管理者開啟管理頁面或完成一次成功操作
- Then 館藏列表顯示書名、ISBN、作者、分類、狀態、可借數／總數及可用動作，且數值與最新業務狀態一致

### AC-004 無館藏時顯示空狀態

- Given 系統沒有任何館藏資料
- When 管理者開啟管理頁面
- Then 館藏區顯示「尚無館藏」及新增書籍引導，且不顯示無效的書籍動作

### AC-005 借書成功更新數量

- Given ISBN 存在、書籍為上架狀態、可借數量大於 0，且管理者已填入借閱人識別資訊
- When 管理者在借書分頁送出 ISBN 與借閱人識別資訊
- Then 借書成功，可借數量減少 1；若數量變為 0 則狀態為「已借出」，否則維持「可借閱」，並顯示成功結果

### AC-006 阻擋不可借書情境

- Given ISBN 不存在、書籍未上架，或書籍可借數量為 0
- When 管理者嘗試借書
- Then 系統拒絕借出，顯示對應的 `A0002`、`A0004` 或 `A0005`，且數量與狀態不變

### AC-007 還書成功恢復數量

- Given ISBN 存在且該書有借閱中的副本
- When 管理者在還書分頁送出 ISBN
- Then 還書成功，可借數量增加 1；若恢復至總數量則狀態為「可借閱」，並顯示成功結果

### AC-008 阻擋無借閱可還

- Given ISBN 不存在，或該書目前沒有借閱中的副本
- When 管理者嘗試還書
- Then 系統拒絕歸還，顯示 `A0002` 或 `A0006`，且數量、狀態與借閱資訊不變

### AC-009 成功與錯誤結果可辨識

- Given 管理者完成新增、借出或歸還操作
- When 後端回傳成功或業務錯誤結果
- Then 前端依 `00000` 或實際業務錯誤碼顯示相應的成功／錯誤回饋，不以 HTTP status 單獨決定畫面結果

### AC-UI-001 前端畫面對齊 Figma 指定來源

- Given 前端以 `docs/figma/library-mini-admin-console/README.md` 所列 Figma URL 與本地 React export 作為視覺參考，並準備相同的新增、借書、還書及空館藏狀態資料
- When QA 逐一比對頁首、借還操作卡、新增書籍表單、館藏列表／空狀態、按鈕／欄位狀態與成功／錯誤提示
- Then 前端主要區塊的結構與順序、控制項文案與狀態、資訊層級及視覺層次均與指定畫面一致；若既有應用程式存在 `data-testid`，其 locator 必須仍可使用

### AC-UI-002 窄畫面對齊

- Given 使用窄畫面檢視指定管理頁面
- When 管理者查看操作區與館藏列表
- Then 操作區可閱讀地改為單欄，列表可水平捲動，必要欄位與借出／歸還動作仍可使用且不遮蓋主要內容

## 錯誤碼（業務層）

| Code | Type | 業務情境 | UI 處理原則 |
| --- | --- | --- | --- |
| `00000` | Success | 操作成功 | 顯示成功訊息並更新相關畫面 |
| `A0000` | Client Error | 通用用戶輸入錯誤 | 顯示可修正的輸入提示 |
| `A0001` | Client Error | 必填欄位缺漏、格式錯誤或數量小於 1 | 保留輸入內容並指出需修正欄位 |
| `A0002` | Client Error | ISBN 找不到對應書籍 | 顯示「找不到該 ISBN 的書籍」類訊息 |
| `A0003` | Client Error | ISBN 已存在 | 顯示不可重複新增的訊息 |
| `A0004` | Client Error | 書籍已無可借副本 | 停止借出並顯示庫存不足訊息 |
| `A0005` | Client Error | 書籍未上架 | 停止借出並顯示不可借閱訊息 |
| `A0006` | Client Error | 書籍沒有借閱中的副本 | 停止還書並顯示無可歸還記錄訊息 |
| `B0000` | System Error | 通用系統處理失敗 | 顯示一般失敗訊息，不揭露內部細節 |
| `B0001` | System Error | 操作結果與館藏狀態不一致或更新失敗 | 不更新畫面為成功，提供重試／重新載入引導 |
| `C0000` | Third-party Error | 本需求目前無第三方依賴 | 保留錯誤類別，若日後使用第三方服務再由 SD 補充 |

## 5) 風險與待確認事項

### 5.1 風險

- R-001 借閱人欄位語意不一致：情境寫「借閱人姓名」，Figma export 顯示「讀者 ID」；若不確認，會造成欄位文案、驗證與 API 命名不一致。
- R-002 多副本追蹤不足：情境要求以借閱紀錄歸還，但 Figma export 的示例狀態以書籍彙總數量呈現，且未提供獨立借閱紀錄清單；多本同 ISBN 同時借出時可能無法精準對應歸還人。
- R-003 逾期／罰款規則未在 scenario 定義：export 內含逾期天數及每日 NT$5 的示例行為，若直接採用可能擴大業務範圍。
- R-004 UI 有搜尋欄但 scope 排除：若誤將搜尋欄視為已實作功能，會造成需求與 API 範圍漂移。
- R-005 Figma export 使用 mock 初始資料；是否需要跨頁面重新整理或跨 session 持久保存，scenario 未明確說明。
- R-006 Figma export 未掃描到 `data-testid`；若 QA 需要穩定 locator，須在 PG／FE 階段建立並固定 locator 清單。

### 5.2 假設

- A-001 `REQ-LIB-001` 與 `SCN-LIB-001` 保持一對一追溯，但需求文件 ID 與 scenario ID 為不同識別碼。
- A-002 本需求以 `docs/figma/library-mini-admin-console/README.md` 的 Figma URL 及本地 export 為指定 UI source of truth；Guidelines 沒有額外限制。
- A-003 「借閱人識別資訊」先作為中性業務用語，以涵蓋 scenario 的姓名與 export 的讀者 ID；在確認前不擴張其他會員資料需求。
- A-004 初始 mock 書籍僅作畫面參考，不視為固定種子資料或驗收筆數。

### 5.3 待確認事項與實作前阻塞

以下事項不阻塞本次 SA 文件交付，但在 Archi／SD 凍結前需取得決策：

- Q-001 借閱人欄位應使用姓名、讀者 ID，或兩者皆需？還書是否必須驗證借閱人？
- Q-002 是否需要可查詢的借閱紀錄，以及多副本同時借出時的精準歸還對應？
- Q-003 是否啟用到期日？未輸入時是否預設 14 天？逾期是否計算每日 NT$5 罰款？
- Q-004 搜尋欄本次是否只做視覺保留，或要另開需求納入搜尋 API？
- Q-005 書籍與借閱資料是否要求跨重新整理／跨 session 保存？
- Q-006 UI 驗收的固定 viewport、Figma frame／節點及可接受視覺差異範圍為何？
- Q-007 應由 FE／QA 確認哪些 `data-testid` locator 作為 E2E 合約？
